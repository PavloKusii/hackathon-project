# Ethical Guard («Етичний Вартовий»)
Команда «NoBypass» · Завдання N 1. Симулятор етичних дилем
## Проблема і користувач
Рішення створене для учасників навчальних та практичних сесій, викладачів і організаторів, а також адміністраторів, яким потрібно відпрацьовувати складні етичні та професійні дилеми на практиці. Часто під час навчання користувачам бракує безпечного інтерактивного середовища, де кожен вибір має наслідки, пояснюється з опорою на норми та аналізується в реальному часі. Організаторам також складно одночасно синхронізувати групу на різних пристроях і бачити загальну картину ризикових рішень та сильних сторін учасників. Це важливо, оскільки помилки в реальних ситуаціях коштують довіри, репутації та ефективності, а системний тренажер дозволяє сформувати виважене мислення ще до виникнення критичного інциденту.
## Що робить рішення
Підтримує проходження лінійних і розгалужених сценаріїв із переходом між вузлами залежно від обраного варіанту.Показує пояснення рішень, помилок та нормативні орієнтири після кроків і у фінальному розборі.   Надає Бібліотеку норм для ознайомлення з правилами та нормативними документами під час підготовки й проходження кейсів.   Забезпечує групові заняття в реальному часі з кодом кімнати, QR-кодом, таймерами та синхронізацією станів між викладачем і слухачами.   Реалізує ролі Гість, Учасник, Організатор і Супер-адміністратор із відповідними правами, створенням/редагуванням сценаріїв та модерацією.   Зберігає історію проходжень учасників, результати занять у JSON та формує групову статистику, проблемні точки і сильні рішення.

## Як запустити
Як запустити
Що потрібно встановити заздалегідь:

Node.js (рекомендовано актуальну LTS-версію) та npm.

Java 17+ (за потреби роботи з супутніми інструментами/сервісами на Java).

Середовище розробки (IDE): IntelliJ IDEA, VS Code або інший зручний редактор коду.

Для групового заняття з інших пристроїв у локальній мережі: усі пристрої мають бути підключені до однієї мережі (наприклад, однієї Wi-Fi мережі).

Команди від клонування до працюючого рішення:

Клонуйте репозиторій та перейдіть у його кореневу теку (git clone <URL_РЕПОЗИТОРІЮ> && cd hackathon-project).

У першому терміналі встановіть залежності та запустіть бекенд (cd backend && npm install && npm start).

У другому терміналі встановіть залежності та запустіть фронтенд (cd frontend && npm install && npm run dev).

Відкрийте адресу фронтенду у браузері та підключіть пристрої учасників до тієї ж локальної мережі для групових сесій.
## Як влаштовано
Стек:Бекенд: Node.js, Express, Socket.IO, файлове JSON-сховище (backend/data/), Java 17+ у середовищі розробки.Фронтенд: React, Vite, Socket.IO Client, qrcode.react.Схема компонентів і де лежить основна логіка:Клієнтські сторінки та компоненти (frontend/src/pages/, frontend/src/components/) відповідають за інтерфейс проходження кейсів, кімнату учасника, панель групового заняття, графіки та статистику.   Клієнтські сервіси (frontend/src/services/) керують HTTP-запитами до API та WebSocket-з'єднанням.   backend/server.js містить точку входу HTTP/Socket.IO-сервера, керує кімнатами (lobby / live / done), таймерами, голосами, станами учасників та розсилками оновлень.   backend/cases.js реалізує валідацію і каталог кейсів, підрахунок балів за шкалами, збереження спроб, сесій і результатів кімнат у JSON, а також REST-ендпоінти.   backend/auth.js відповідає за автентифікацію користувачів та перевірку ролей.   Які правила ухвалюють висновки в системі:Усі оцінки та висновки формуються детермінованими правилами коду на основі обраних варіантів відповіді та числових змін (deltas) за шкалами доброчесності, довіри/репутації та ефективності (базове значення 100, межі 0..100, зміна за вибір у межах -40..0).   Фіксація помилок і ризикових кроків визначається порівнянням балів обраного варіанта з найкращим/безпечним варіантом кроку та наявністю від'ємних змін за шкалами.   Групові підсумки, середні значення, проблемні точки (кроки з найбільшою часткою ризикових виборів/втрат балів) та сильні рішення (кроки з виборами без втрат балів) обчислюються безпосередньо за збереженими відповідями й балами учасників. 
Які правила ухвалюють висновки в системі (пункт 4 Політики використання ШІ).

## Що використали
Node.js — серверне середовище виконання JavaScript (використано для HTTP-сервера та логіки бекенду).   Express — вебфреймворк для Node.js (використано для REST API бекенду).   Socket.IO — бібліотека двостороннього зв'язку в реальному часі (використано для синхронізації кімнат і подій між викладачем та учасниками).   React — бібліотека для побудови користувацького інтерфейсу (використано для сторінок і компонентів фронтенду).   Vite — інструмент збірки та локального сервера розробки фронтенду.qrcode.react — React-компонент для генерації QR-кодів (використано для швидкого входу учасників у кімнату).   Java (JDK 17+) — платформа розробки (зазначена у вимогах середовища розробки).IntelliJ IDEA / VS Code — інтегровані середовища розробки / редактори коду (використано для написання та налагодження коду).
